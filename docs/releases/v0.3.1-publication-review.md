# Nicos Catalog v0.3.1 publication review

Review date: 2026-08-20.

## Candidate verdict

`v0.3.1` is a compatible release-integrity patch. The candidate passes the
local publication, fuzz, security, performance, static deployment, and browser
gates. The public tag, GitHub Release, public-proxy install, and exact
release-bound deployment are not yet recorded in this review.

Do not claim that the candidate is released until those remote facts exist.
Remote readback must confirm each fact.

## Defects found and repaired

- Public URL projection accepted an at-sign in a raw URL path. The projection
  now rejects raw and decoded credential markers, with unit and fuzz regression
  coverage.
- The fuzz worker limit did not also bind Go scheduler concurrency. The Make
  target now binds both values and the full seven-target suite passes on a
  shared host.
- The publication-note heading test assumed LF even when Git converted the
  file to CRLF on Windows. The test now accepts both line-ending forms and has
  direct regression cases.
- The `v0.3.0` GitHub Release body contained stale pre-publication status. It
  now matches the checked-in timeless release notes, and the immutable tag
  target did not move.

## Release signature policy

The repository contains `.github/allowed_signers`. Release operators configure
Git SSH signing, create an annotated signed tag, and run `git verify-tag`
before push.

The release key is not yet registered as a GitHub signing key. Therefore the
tag can be cryptographically signed and independently verified while GitHub's
account-level “Verified” label remains absent. These are separate facts.

## Candidate deployment

The synthetic static Explorer is reachable at
`https://nicos-catalog-explorer.pages.dev/`. Candidate verification checked all
15 files, direct application routes, and the public manifest. A final deploy
from the exact release commit is required before this review records the
deployment as release-bound.

## Lifecycle boundary

independent adoption, active use, retention, or revenue. A hosted synthetic
demo proves deployment only after it is bound to the released source.
