# Nicos Catalog v0.3.1 publication review

Review date: 2026-08-20.

## Verdict

`v0.3.1` is public, released, proxy-installable, and deployed as a synthetic
static Explorer. The release, distribution, and deployment facts all trace to
commit `f49236dfe520f94058ac802ca7ad9c6e5b2bb7c5`.

The annotated tag has a valid SSH signature under the repository-owned signer
policy. GitHub reports `unknown_key` because the account has not registered the
key as a signing key. This missing account badge does not invalidate the
independently verified signature. It remains a public backlog item.

## Defects found and repaired

- Public URL projection accepted an at-sign in a raw URL path. The projection
  now rejects raw and decoded credential markers, with unit and fuzz regression
  coverage.
- The fuzz worker limit did not also bind Go scheduler concurrency. The Make
  target now binds both values and the full seven-target suite passes on a
  shared host.
- The publication-note heading test assumed LF even when Git converted the
  file to CRLF on Windows. The test now accepts both line-ending forms and has
  direct regression cases.
- The `v0.3.0` GitHub Release body contained stale pre-publication status. It
  now matches the checked-in timeless release notes, and the immutable tag
  target did not move.

## Release signature policy

The repository contains `.github/allowed_signers`. Release operators configure
Git SSH signing, create an annotated signed tag, and run `git verify-tag`
before push.

The release key is not registered as a GitHub signing key. Therefore the tag is
cryptographically signed and independently verified while GitHub's
account-level “Verified” label remains absent. These are separate facts. Public
[issue 3](https://github.com/nstranquist/nicos-catalog/issues/3) tracks the
account action and later enforcement.
